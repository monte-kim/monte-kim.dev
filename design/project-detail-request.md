# 디자인 요청: 프로젝트 상세 페이지 (/projects/[slug])

monte-kim.dev에 **프로젝트 상세 페이지**를 추가합니다. 이 페이지가 사이트의 포트폴리오 역할을 맡습니다.

## 배경 & 정보 구조

현재 /projects(2b)는 카드 그리드까지고, 깊은 이야기는 블로그 케이스 스터디가 담당합니다.
그 사이에 "이 프로젝트가 무엇인지"를 2분 안에 파악시키는 층이 없어서 신설합니다:

**카드(3초 스캔) → 상세 페이지(2분, 포트폴리오 허브) → 케이스 스터디(10분, 깊이) → GitHub(코드)**

## 필요한 화면

- **2k** — 데스크톱 프로젝트 상세 (1200px). 레퍼런스 콘텐츠는 Muroom (아래 §섹션 구성)
- **3f** — 모바일 상세 (390px)
- **2b 수정** — 카드 전체가 상세로 클릭되는 인터랙션 반영 (카드 하단 링크 행에 "Details →"를 추가할지, 카드 전체 클릭+기존 링크 유지일지는 디자인 판단에 맡김)
- 다크는 기존 토큰 체계로 자동 (별도 화면 불필요, 특이 처리 있을 때만 명시)

## 섹션 구성 (위→아래 순서 제안 — 조정 가능)

1. **히어로**: 브레드크럼(← Projects) · 프로젝트명 + 역할 배지(Founder 등) · 원라이너 · 액션 링크(GitHub ↗, Case study →)
2. **스탯 스트립**: 실측 수치 4~6개 (홈 2a의 3셀 스탯 스트립 패턴 참조·확장) — 예: 130 studios · 1,273 rooms · ~$150/mo infra · beta in 3 weeks
3. **제품 소개**: 2~3문단 + **제품 스크린샷 1~2장** (스크린샷 프레임 처리 방식 정의 필요 — 보더/라운딩/그림자)
4. **아키텍처**: 개요 1문단 + **아키텍처 다이어그램 영역** (다이어그램 자체의 시각 언어 정의: 노드 박스/연결선 스타일 — 사이트 토큰으로. 노드 구성 예: Client → ALB → ECS(Spring Boot) → PostgreSQL+PostGIS / Valkey, S3, Secrets-rotation Lambda, NAT instance)
5. **스택**: 전체 기술 목록 그룹핑 (App / Data / Infra / Ops) — 태그 칩 패턴 확장
6. **역할 분담**: 5인 팀 구성 + 내가 소유한 영역 명시 (정직한 서술이 컨셉 — "Led everything"이 아니라 소유 영역 구분)
7. **타임라인**: 마일스톤 5~7개 (about 2c의 "Path so far" 2열 그리드 패턴 재사용 가능)
8. **의사결정 하이라이트**: 4~6개 항목, 각 1~2문장 + 해당 케이스 스터디 글로 링크 (링크 없는 항목도 있음)
9. **푸터 CTA**: 케이스 스터디 시리즈 전체 링크 + Say hi

## 지켜야 할 것

- 기존 토큰/타이포/라디우스/아이콘 체계 (README의 Design Tokens 섹션 그대로)
- 산출물은 기존 방식: 캔버스에 인라인 스타일 HTML 섹션으로 화면 id 추가 (2k, 3f, 2b′)
- 카피: 아래 Muroom 레퍼런스 카피를 사용하되, **최종 확정 카피는 도시에(분석) 세션의 콘텐츠 패키지가 곧 제공됨** — 구조·길이감은 이 브리프 기준으로 확정, 문구는 근사치로 취급
- 서비스가 2026-08 종료 예정이라 "wound down" 상태 표기를 어딘가에 정직하게 담는 것 고려 (히어로 배지 or 타임라인 마지막)
